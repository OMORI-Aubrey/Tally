# 📊 Tally

**어디서 샜는지 보여주고, 다음 한 걸음을 제안합니다.**

공부 세션이 **몇 조각으로 부서졌는지**를 자동으로 복원해 보여주는 Android 앱입니다. 타이머를 켜고 공부한 뒤 끄면, 그 사이 스마트폰을 언제 어떤 앱으로 열었는지를 OS 사용 기록에서 되살려 "가장 길게 이어간 시간"과 "끊긴 횟수"를 셉니다. 기록은 기기 밖으로 나가지 않습니다.

> "몇 시간"이 아니라 "몇 조각"이 이 앱의 1차 질문입니다.

## 진행 상황

기획서 §13의 단계 P0~P7을 이슈 단위로 진행합니다. 자세한 작업과 결정은 [PLAN.md](PLAN.md)에 있습니다.

| 단계 | 상태 | 내용 |
|---|---|---|

| P1 세션이 기록된다 | ✅ | 디자인 토큰, 내비게이션, 타이머, 과목, 기록 탭 세션 목록 |

## 지금 되는 것

**타이머**
- 과목(선택)을 고르고 시작한다. 과목은 최근 5개가 칩으로 나오고, 시트에서 추가·이름 바꾸기(과거 세션까지 소급)·숨기기를 한다. 삭제는 없다
- 진행 중에는 경과 시간·과목·종료 버튼만 보인다. 앱을 강제 종료해도 세션이 그대로 이어지고, 재부팅했으면 다시 열 때 이어서 기록할지 삭제할지 묻는다
- 대기 화면 위쪽에 `이번 주 최장 47분 · 평균 28분 →` 한 줄. 누르면 기록 탭으로 간다

**세션 종료 → 체감 입력 → 리포트**
- 종료하면 사용 기록을 한 번 조회해 타임라인을 복원하고 지표를 계산해 저장한다
- 주 1회만, 예측할 수 없게(1/3 확률, 그 주 3번째 세션이면 확정) 실측을 보기 **전에** "몇 분 정도 집중한 것 같나요?"를 묻는다
- 세션 리포트는 위에서부터
  - 격차 포스트잇(체감을 적은 세션만): `체감 2시간 / 실측 최대 1시간 28분 / +36% 과대평가`
  - 구조 헤드라인: `최장 34분 · 6조각`, `세션 1시간 38분 중 34%`, `기록 47분`
  - 타임라인 스트립: 세션 전체를 한 막대에 구간 길이 그대로(허용 앱·화면 꺼짐·딴짓·화면 켜짐·자리 비움)
  - 총량: `순공 최대 1시간 28분` / `공부 1시간 38분 · 딴짓 10분`
  - 지표 카드(집중 밀도·세션 길이), 딴짓한 순간 목록, 미분류 앱 질문(세션당 2개), 세션 메타
- 리포트에서 앱 분류를 고치면(미분류 앱 질문에 답하거나 이탈 목록을 길게 눌러 `허용`) 그 세션을 다시 조회해 바로 다시 계산한다

**기록 탭**
- 날짜별 세션 목록. 3분 미만 세션과 종료를 잊은 180분 초과 세션은 남기되 연필 가운뎃줄로 지우고 통계에서 뺀다. 누르면 그 세션의 리포트가 열린다

**설정 탭**
- 앱 분류: 공부 중 감지된 앱만 모아 `딴짓 | 허용`을 고른다. 바꾼 분류는 다음 세션부터 반영된다

## 동작 방식

```
[1] 타이머 시작        과목(선택)을 고르고 세션 시작
[2] 세션 진행          앱은 아무것도 하지 않는다. 차단도, 알림도 없다
[3] 타이머 종료
[4] 타임라인 복원      UsageStatsManager.queryEvents로 세션 구간의 이벤트를 한 번에 조회
[5] (주 1회) 체감 질문  "방금 세션에서 몇 분 정도 집중한 것 같나요?"
[6] 세션 리포트        최장 구간 · 조각 수 · 타임라인 스트립 · 순공 · 딴짓 · 이탈 목록
[7] 기록 화면          세션 목록 (판정 · 다음 목표 · 주간 집계는 P6)
```

포그라운드 서비스 없이, 종료 시점에 OS가 남긴 원본 이벤트로 복원합니다. 배터리를 쓰지 않고 Doze에도 영향받지 않습니다.

```
19:00 ─────────────────────── 19:34 ──── 19:41 ──────────── 20:12 ── 20:15 ───────── 20:38
    ■■■■■■■■■■■■■■■■■■■■■■■■■  ▓▓▓▓▓▓▓  ■■■■■■■■■■■■■■■■■  ▓▓▓▓  ■■■■■■■■■■■■
       학습 34분                YouTube 7분      학습 31분         카톡 3분   학습 23분

    공부 98분 · 순공 최대 88분 · 딴짓 10분 · 최장 34분 · 3조각
```

복원 규칙(§6.2)의 요점은 다음과 같습니다.

- 앱 전환·화면 켜짐/꺼짐·잠금 해제 이벤트로 구간을 만든다. 잠금을 풀고 홈 화면에 머문 시간은 딴짓이 아니다
- 5초 미만 구간은 앞뒤에 흡수한다. 화면만 켜고 앱을 열지 않은 구간은 10초까지 흡수한다
- 화면이 60분을 넘게 꺼져 있었으면 리포트 전에 공부했는지 자리를 비웠는지 묻는다. 자리 비움은 공부 시간과 순공에서 빠지고 최장 구간도 끊는다. 자리 비움을 빼고도 180분이 넘으면 종료를 잊었는지 묻는다
- 구간들이 세션 전체를 빈틈 없이 덮는지 검사한다(불변식)

## 지표

**1차 지표 — 세션 구조**

| 지표 | 정의 |
|---|---|
| 최장 무방해 구간 `LFS` | 딴짓 없이 이어간 구간 중 가장 긴 것. 앱의 대표 지표 |
| 이탈 횟수 `N_int` | 딴짓 구간의 개수. 화면에는 `N_int + 1`조각으로 쓴다 |

**2차 지표 — 시간 총량**

| 지표 | 정의 |
|---|---|
| 착석 시간 `T_total` | 세션 길이에서 자리 비움을 뺀 시간. 화면에는 **"공부"**로 쓴다 |
| 딴짓 시간 `T_dist` | 딴짓 구간 길이의 합 |
| 순공시간 `T_focus` | `T_total − T_dist`. 폰 밖의 딴짓은 잴 수 없어 상한 추정이므로 항상 **"최대"**를 붙인다 |
| 집중 밀도 `D` | `T_focus / T_total × 100` (%) |
| 인식 격차 `G` | `(체감 − 순공) / 순공 × 100` (%). 양수가 과대평가. 저장하지 않고 볼 때 계산한다 |

앱은 `딴짓` / `허용` 두 가지로만 분류하며, 화면이 꺼진 구간은 순공에 넣습니다. 판정과 목표(P6)는 절대 기준이 아니라 **최근 4주 개인 기준선**과 비교해 냅니다.

### 앱 자동 분류

**기본은 딴짓입니다.** 모르는 앱이 순공에 섞이면 "순공 최대"가 부풀려지기 때문입니다. 아래만 허용으로 시작합니다.

- 본 앱, 기본 홈 앱
- 공부 앱 목록(줌·Meet·Teams·클래스룸·사전·번역·노트 등)
- 시스템 앱. 다만 브라우저·전화·SNS·영상·게임은 시스템 앱이어도 딴짓

자동 분류는 틀리는 것이 기본이라고 보고 고치는 길을 짧게 둡니다. 리포트의 미분류 앱 질문이나 이탈 목록 길게 누르기로 그 세션까지 바로 고칠 수 있고, 설정의 앱 분류 화면에서는 다음 세션부터 바뀝니다. 사용자가 정한 분류는 자동 분류가 덮어쓰지 않습니다. (기획서 §5.1의 "미지정 → 허용"과 다르며, 근거는 PLAN.md §4에 있습니다.)

## 설계 원칙

```
총량이 아니라 구조를 센다  →  남과 비교하지 않는다  →  다음 한 걸음을 제안한다
```

- **차단하지 않는다.** 차단하면 데이터가 남지 않는다. 대신 정확하게 기록하고 정직하게 보여준다.
- **비교 대상은 언제나 자기 자신이다.** 랭킹·그룹·공유 기능이 없고, 계정도 서버도 없다.
- **압박하지 않는다.** 판정과 목표는 기록 탭 안에만 둔다. 공부를 시작하는 타이머 화면에는 숫자 한 줄만 보인다.
- **원인을 단정하지 않는다.** "유튜브 때문에 집중이 깨졌다"가 아니라 함께 일어난 일로만 쓴다(§5.5).
- **0을 보이지 않는다.** `0회`, `0분`, `0%` 대신 문장으로 쓴다. 이탈이 없으면 "이 세션에는 이탈이 없었어요".

**디자인 — 종이 노트.** 줄 노트 바탕에 손글씨 글꼴(개구체, 나눔손글씨 펜체), 형광펜·마스킹테이프·포스트잇으로 꾸밉니다. 숫자 강조와 판정은 파란 볼펜으로 쓰고, 빨간 펜은 목표 달성 도장과 과대평가 표시 두 곳에만 씁니다. 라이트 모드 전용입니다. 색과 글자 스타일은 `ui/theme/Color.kt`, `Type.kt`의 토큰만 씁니다.

## 아키텍처

```
   Compose UI
       ↕ StateFlow
   ViewModel
       ↓
   도메인 로직 (순수 Kotlin 함수 — 단위 테스트 대상)
    ├── TimelineReconstructor      ✅ 원본 이벤트 → 구간
    ├── MetricsCalculator          ✅ 구간 → 지표 6개 + 인식 격차
    ├── BaselineCalculator         P6
    ├── VerdictResolver            P6
    ├── GoalSuggester              P6
    └── TemplateReportGenerator    P7
       ↓
   Repository
       ↓
   Room (단일 진실 공급원) · DataStore · UsageStatsManager
```

UseCase 계층은 두지 않습니다. 알고리즘 성격이 강한 6개만 도메인 순수 함수로 분리하고, 나머지는 ViewModel이 Repository를 직접 호출합니다. `domain`은 Android에 의존하지 않으며 테스트(`DomainPurityTest`)로 이를 지킵니다.

```
com.jaeyun.tally
├── TallyApplication, AppContainer, MainActivity
├── ui/        theme, components(공용 컴포저블, 모두 @Preview), screens(화면별 Screen + ViewModel)
├── domain/    model, reconstructor, metrics, baseline, verdict, goal, report
├── data/      room, usagestats, datastore, repository
└── util/      주 범위, 시간 표기, 조사 등
```

## 빌드와 실행

**요구 사항**

- Android Studio — AGP 9.4.1을 지원하는 버전. Studio가 지원하지 않는 AGP로 올리면 동기화가 깨지므로, AGP·Gradle은 Studio를 먼저 업그레이드한 뒤 올린다
- Android SDK Platform 37
- JDK 21 (Gradle daemon toolchain. 없으면 자동으로 받는다)

```bash
./gradlew assembleDebug        # 디버그 APK
./gradlew testDebugUnitTest    # JVM 단위 테스트
./gradlew lintDebug            # 린트
./gradlew installDebug         # 연결된 기기에 설치
```

**실기기에서 확인합니다.** 에뮬레이터에는 앱 사용 기록이 거의 없어 타임라인 복원을 검증할 수 없습니다. Android Studio에서 무선 디버깅으로 연결해 실행 버튼을 누르면 됩니다.

**사용 기록 권한을 직접 켜야 합니다.** 앱은 `PACKAGE_USAGE_STATS` 특수 권한을 씁니다. 런타임 팝업으로 요청할 수 없으므로 설정의 **사용 기록 접근**(기기에 따라 "사용 정보 접근")에서 Tally를 허용해야 합니다. 권한이 없으면 타이머만 동작하고 공부 시간만 기록됩니다. 처음 열면 나오는 온보딩의 [권한 설정하기]로 설정 화면을 열 수 있습니다. [나중에 하기]로 넘어갔다면 설정에서 직접 켜거나 아래 프로브에서 설정 화면을 엽니다.

**사용 기록 프로브 (debug 전용).** debug 빌드를 설치하면 런처에 "Tally 프로브" 아이콘이 함께 생깁니다. 권한 상태, 원본 이벤트 덤프, 앱 자동 분류 결과, 마지막 세션의 저장값과 구간, 이번 주 체감 질문 상태를 보여주고, 진행 중 세션에 시간을 더하는 임시 도구, 화면 꺼짐 확인 다이얼로그 기준을 60분에서 1분으로 낮추는 임시 스위치, 세션 기록은 그대로 둔 채 온보딩을 다시 띄우는 버튼도 있습니다. 끄려면 `-Ptally.probe=false`로 빌드합니다. release 빌드에는 들어가지 않습니다.

> ⚠️ 프로브는 Tally 안의 화면이라 프로브 아이콘을 지우면 Tally 전체가 삭제됩니다. 앱을 삭제하면 세션 기록과 사용 기록 권한도 함께 사라집니다. `./gradlew connectedDebugAndroidTest`도 끝나면 앱을 지웁니다.

## 기여 규칙

이슈 하나에 브랜치 하나로 작업하고, 실기기 확인을 마친 뒤 커밋합니다. 이슈와 PR은 `.github/`의 템플릿을 따릅니다.

커밋 메시지는 `[커밋태그/#이슈번호] 제목` 형식을 따릅니다. 이슈 번호가 없으면 `[커밋태그] 제목`.

```
[feat/#12] 세션 종료 파이프라인
[chore] 린트 규칙 정리
```

- 커밋 태그: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`
- 브랜치 이름: `커밋태그/#이슈번호-설명` (예: `feat/#12-session-end-pipeline`)
