## 세션 지표 6개

`MetricsCalculator.calculate(segments, sessionStart, sessionEnd)`가 구간을 한 번 훑어 계산한다.

| 지표 | 저장 필드 | 계산 | 화면에서 |
|---|---|---|---|
| 착석 `T_total` | `tTotalSec` | 세션 길이(종료 − 시작) − 자리 비움(`AWAY`) 구간 합. 음수면 0 | **"공부"** (`공부 1시간 38분`) |
| 딴짓 `T_dist` | `tDistSec` | `DISTRACT` 구간 길이의 합. 화면만 켜진 구간(`__SCREEN_ON_UNKNOWN__`)도 딴짓이다 | `딴짓 10분` |
| 순공 `T_focus` | `tFocusSec` | `T_total − T_dist`. 허용 앱과 화면 꺼짐이 순공에 들어간다 | 늘 "최대"를 붙인다 (`순공 최대 1시간 28분`) |
| 최장 무방해 구간 `LFS` | `lfsSec` | `ALLOWED`·`SCREEN_OFF` 구간이 이어진 길이 중 가장 긴 것. `DISTRACT`와 `AWAY`가 연속을 끊는다 | `최장 34분` — 리포트에서 가장 큰 숫자 |
| 이탈 `N_int` | `interruptionCount` | `DISTRACT` 구간의 개수. 바로 붙은 `DISTRACT`는 하나로 센다 | 조각 수 `N_int + 1` (`6조각`) |
| 집중 밀도 `D` | `densityPct` | `T_focus / T_total × 100`. 착석이 0이면 0 | 지표 카드 `집중 밀도 87%` |

구간 분류별로 정리하면 이렇다.

| 분류 | 착석 | 순공 | 딴짓 | 최장 구간 연속 |
|---|---|---|---|---|
| `ALLOWED` 허용 앱(본 앱 포함) | 들어감 | 들어감 | — | 이어짐 |
| `SCREEN_OFF` 화면 꺼짐 | 들어감 | 들어감 | — | 이어짐 |
| `DISTRACT` 딴짓 앱·화면만 켜짐 | 들어감 | 빠짐 | 들어감 | 끊김 |
| `AWAY` 자리 비움 | 빠짐 | 빠짐 | — | 끊김(시간도 더하지 않음) |

예: `공부 30분 → 자리 비움 1시간 → 공부 20분`이면 `LFS`는 30분이다. 자리 비운 앞뒤를 이으면 실제로 없던 50분짜리 집중이 생기기 때문이다(PLAN.md §4 "`AWAY`와 `LFS`").

### 초 단위와 버림

- 구간은 millis로 다루고, 저장할 때 초 단위로 **버린다**. 그래서 순공이 실제보다 커지지 않는다.
- `tDistSec`는 `tTotalSec`를 넘지 않게 자르고, `tFocusSec = tTotalSec − tDistSec`로 낸다. 저장값에서 `순공 + 딴짓 = 착석`이 늘 맞는다.
- `densityPct`는 버리기 전의 millis로 계산한 실수(Float)다. 화면은 정수로 버려 쓴다.

## 인식 격차 `G`

`MetricsCalculator.perceptionGapPct(perceivedFocusMin, tFocusSec)`

```
G = (체감 분 − 순공 분) / 순공 분 × 100     (순공 분 = tFocusSec / 60, 소수)
```

- **양수가 과대평가**다. 모든 화면이 이 부호를 쓴다.
- 체감을 적지 않았거나 순공이 0초면 null이다(0으로 나누지 않는다).
- 저장하지 않는다. 리포트는 반올림한 정수로 보여 준다: `+36% 과대평가`(빨간 펜 동그라미), `-12% 과소평가`(파란 볼펜), 0%면 `체감과 실측이 같아요`.
- 타임라인이 없는 세션(권한 없이 끝냄)은 체감 값이 있어도 격차를 보이지 않는다.

## 체감 질문 (주 1회)

세션을 끝낸 뒤 리포트 **전에** 실측을 보여 주지 않고 체감 집중 시간을 묻는다. 물을지는 `shouldAskPerceived`([`TimerViewModel.kt`](../../app/src/main/java/com/jaeyun/tally/ui/screens/timer/TimerViewModel.kt))가 정한다.

1. 방금 끝낸 세션이 **통계에 셀 세션**(`countsInStats`)이 아니면 묻지 않는다. 3분 미만·180분 초과·권한 없는 세션에 그 주의 한 번을 쓰지 않는다.
2. 그 세션이 시작한 주에 이미 물었으면 묻지 않는다. "물었다"는 `perceivedAskedAt`(마지막으로 물은 세션의 시작 시각)이 이번 주 안이거나, 이번 주 세션 중 체감 값이 있는 세션이 있다는 뜻이다. **건너뛰어도 물은 것으로 친다.**
3. 1/3 확률로 묻는다. 이번 주의 통계 세션 중 이 세션이 3번째 이후면 확정으로 묻는다.

물기로 정하면 화면을 띄우기 **전에** `perceivedAskedAt`을 적는다. 답하지 않고 앱을 닫아도 그 주에는 다시 묻지 않는다.

**입력 규칙** ([`PerceivedInputViewModel.kt`](../../app/src/main/java/com/jaeyun/tally/ui/screens/perceived/PerceivedInputViewModel.kt))

- 미리 채운 숫자 없이 빈칸에 숫자 키패드로 적는다.
- 적을 수 있는 최대값은 **타이머 길이**(종료 − 시작, 분 단위 올림)다. 착석이 아니다 — 자리 비움으로 빠진 시간에도 폰 밖에서 공부했을 수 있다.
- 최대값이 60분 이상이면 시간 칸(한 자리)과 분 칸(두 자리, 0~59)을 따로 둔다. 60분 미만이면 분 칸만 둔다.
- 한 칸만 적으면 다른 칸은 0으로 본다. 0분도 받는다.
- 최대값을 넘으면 `2시간 30분까지 적을 수 있어요`, 분 칸에 60 이상을 적으면 `분은 59까지 적을 수 있어요`.

## 통계 포함 기준

`StudySession.isValidForStats`. 기록은 남기고 통계에서만 뺀다.

| 조건 | 결과 |
|---|---|
| 착석(`tTotalSec`)이 180초 이상 10,800초(180분) 이하 | 통계에 넣는다(경계 포함) |
| 착석 3분 미만 | 뺀다(오조작) |
| 착석 180분 초과 | 일단 뺀다. ② 다이얼로그 `[계속 공부했어요]`면 넣는다 |
| 타임라인 불변식 위반 | 뺀다(release). debug는 예외로 멈춘다 |

- 착석으로 재므로 자리 비움을 빼고 판단한다. 자리 비움이 없으면 세션 길이와 같다.
- `SessionValidity`는 지표 정의가 아니다. 3분·180분을 바꿔도 지표 규칙 버전을 올리지 않고 `isValidForStats`만 다시 계산하면 된다.

**통계에 셀 세션** = `isValidForStats && hasTimeline` (`countsInStats`). 권한 없이 끝낸 세션은 `LFS`가 없어 숫자에 섞으면 0이 보이기 때문이다. 쓰는 곳:

| 쓰는 곳 | 기준 |
|---|---|
| 타이머 주간 요약 줄 | 이번 주에 시작한 `countsInStats` 세션의 `LFS` 최댓값·평균 |
| 체감 질문 후보, "이번 주 3번째" | `countsInStats` 세션만 센다 |
| 리포트의 `기록 47분` | 이 세션을 뺀 `countsInStats` 세션의 `LFS` 최댓값. 이 세션도 `countsInStats`일 때만 줄을 둔다 |
| 기준선·판정·이번 주 목표·목표 달성 | `countsInStats` 세션만(`SessionStats.countsInStats`, `WeekStats.of`) |
| 기록 탭 이번 주 섹션·누적·요약 문단 | `countsInStats` 세션만. 세션 목록에는 모든 끝난 세션이 남는다 |
| 기록 탭 세션 목록 | `isValidForStats`가 false면 연필 가운뎃줄 |

## 주간 요약 줄의 숫자

타이머 IDLE의 `이번 주 최장 47분 · 평균 28분 →` — `weeklySummary`([`TimerViewModel.kt`](../../app/src/main/java/com/jaeyun/tally/ui/screens/timer/TimerViewModel.kt)).

- `최장` = 이번 주(월요일 00:00 시작)에 시작한 `countsInStats` 세션의 `LFS` 최댓값
- `평균` = 같은 세션들의 `LFS` 평균(초에서 버림). 세션 길이 평균이 아니다
- 셀 세션이 없거나 최댓값이 0초면 숫자 대신 `첫 세션을 시작해보세요`(누를 수 없다)

## 기준선

`BaselineCalculator.calculate(sessions, thisWeekStartAt, zone, requiredSessions)` — 판정과 목표의 근거. 저장하지 않는다.

- **기간**: 이번 주를 **뺀** 직전 4주. 이번 주 월요일 00:00의 4주 전 월요일 00:00부터다(`windowStartAt`, 날짜로 계산해 일광 절약 시간이 바뀌어도 00:00). 세션은 시작한 주에 속한다.
- **대상**: 그 기간에 시작한 `countsInStats` 세션.
- **활성 조건**: 12세션(`REQUIRED_SESSIONS`). 설정 탭 개발자 영역의 기준선 완화를 켠 **debug 빌드**는 6세션(`requiredSessions(relaxed, debugBuild)`). 모자라면 `Inactive(neededSessions)` — 화면은 `기준선 계산에 세션 N개가 더 필요합니다`.

| 값 | 계산 | 쓰는 곳 |
|---|---|---|
| 집중 밀도 | `Σ T_focus / Σ T_total × 100` — 세션 평균이 아니라 기간 합이라 긴 세션이 더 반영된다 | 판정, 판정 근거 `(평소 71%)`(정수로 버림) |
| 세션당 이탈 | `Σ N_int / 세션 수` | 목표 |
| 평균 최장 구간 | 세션 `LFS`의 평균(초에서 버림) | 판정 근거 `최장 평균 34분 (평소 38분)`, 목표 |
| 주간 순공 | `Σ T_focus / 4` — 세션이 없는 주가 있어도 4로 나눈다 | 판정 근거 `순공 최대 21h (평소 19h)`, 총량 가드, 목표 |
| 평균 세션 길이 | 공부 시간(`T_total`)의 평균 | 보이지 않는다. 목표의 세션 길이 가드만 쓴다 |

한 주의 값(`WeekStats.of`)도 같은 정의다. 순공만 4로 나누지 않은 그 주의 합이다. 그 주에 `countsInStats` 세션이 없으면 null이다.

## 판정

`VerdictResolver.resolve(이번 주 밀도, 이번 주 순공, 기준선)` — 기준선이 활성이고 이번 주에 `countsInStats` 세션이 있을 때만 부른다. 이번 주 밀도도 기간 합이다.

```
편차 = (이번 주 D − 기준선 D) × 100 / 기준선 D     (곱셈을 먼저 해 경계값에서 소수 오차가 나지 않게)
```

| 편차 | 판정 | 문구 |
|---|---|---|
| +10% 이상 | `BEST` | `지난 4주 중 가장 잘한 주예요` |
| +3% 이상 +10% 미만 | `BETTER` | `지난 4주보다 잘하고 있어요` |
| −3% 초과 +3% 미만 | `STEADY` | `평소 페이스를 유지했어요` |
| −10% 초과 −3% 이하 | `SLIPPED` | `최장 구간 47분을 만들었어요. 딴짓은 조금 늘었네요` |
| −10% 이하 | `TOUGH` | `이번 주 최장 구간은 47분이었어요. 조금 힘든 주였네요` |

- 경계값(±3%, ±10%)은 바깥(더 강한) 구간에 넣는다.
- 기준선 밀도가 0이면 이번 주가 0보다 클 때 `BEST`, 같을 때 `STEADY`다.
- 부정적인 두 구간은 이번 주 `LFS` **최댓값**을 먼저 말한다(성취를 먼저, §5.6).
- **총량 가드** — 이번 주 순공 < 기준선 주간 순공 × 0.7이면 판정을 `STEADY`보다 올리지 않는다(`minOf(판정, STEADY)`). 단방향이라 순공이 많은 주에 판정을 올리지는 않는다.
- 가드가 판정을 실제로 내렸을 때만(원래 `BETTER`·`BEST`) `clamped = true`이고, 판정 문구 대신 `이번 주는 짧게 자주 하셨네요. 집중 밀도는 82%로 좋았어요`와 근거 `집중 밀도 82% · 4주 기준선 71%`를 쓴다. 원래 `STEADY` 이하면 가드 조건이 맞아도 원래 문구다.
- 판정은 늘 **이번 주**다. 기록 탭에서 지난 주를 골라도 판정은 바뀌지 않는다.

## 이번 주 목표

`GoalSuggester.suggest(지난주 값, 기준선)` — 끝난 지난주 값(`WeekStats`)을 지난주를 뺀 직전 4주 기준선과 견줘 목표 하나를 고른다. 기준선이 미활성이거나 지난주에 `countsInStats` 세션이 없으면 목표가 없다. 만들고 저장하는 흐름은 [03-data](03-data.md#weeklygoal--주간-목표).

| 순위 | 조건(지난주 vs 기준선) | 목표 지표 | 목표값 |
|---|---|---|---|
| 1 | 세션당 이탈 ≥ 기준선 × 120% **이고** 기준선보다 많다 | 세션당 이탈 | 기준선(복귀) |
| 2 | 평균 `LFS` < 기준선 × 90% | 최장 평균 | 기준선 |
| 3 | 주간 순공 < 기준선 주간 순공 × 90% | 주간 순공 | 기준선 |
| 4 | 모두 정상 | 가장 덜 좋아진 지표 | 좋아지는 방향으로 5% — 이탈은 × 95%, 나머지는 × 105% |

- **4순위의 "가장 덜 좋아진 지표"** — 좋아지는 방향으로 부호를 맞춘 기준선 대비 편차(이탈은 줄어야 +)가 가장 작은 지표. 같으면 이탈 → `LFS` → 순공 순서. 기준선 값이 0이면 같을 때 0, 좋아졌으면 +∞, 나빠졌으면 −∞로 본다.
- **세션 길이 가드** — 지난주 평균 세션 길이가 기준선의 ±20% **밖**이면(경계값은 안) 2순위와 4순위 모두에서 `LFS`를 뺀다. `LFS`는 세션 길이가 상한이라, 세션을 길게·짧게 바꾼 주의 `LFS` 변화는 집중력 변화가 아니다.
- 경계값(120%, 90%, ±20%)은 퍼센트 정수로 곱해 비교한다.
- 전체 기간 최고 기록은 입력으로 받지도 않는다. 목표는 대부분 "평소만큼 하기"다.
- 단위: 세션당 이탈은 회(소수 첫째 자리에서 반올림, `.0`은 쓰지 않는다 — `3.4회`, `3회`), 최장 평균은 분(`40분`), 주간 순공은 분(총량 표기 `10h 30m`).

### 목표 달성

`GoalSuggester.isAchieved(지표, 그 주 값, 목표값)` — 목표를 둔 주가 끝난 뒤 그 주 `countsInStats` 세션 값으로 판정한다(`WeeklyGoal.judged`).

- 세션당 이탈은 목표 **이하**, 최장 평균·주간 순공은 목표 **이상**이면 달성이다(목표값과 같아도 달성).
- 그 주에 `countsInStats` 세션이 없었으면 견줄 값이 없어 미달성(`achievedValue = null`).
- 화면에는 **달성한 지난주 목표만** 보인다(빨간 펜 도장). 미달성은 아무것도 보이지 않는다.

## 기록 탭 이번 주 섹션의 숫자

`buildWeekSection` — 고른 주(첫 기록의 주 ~ 이번 주)에 시작한 `countsInStats` 세션으로 낸다. 그 주에 셀 세션이 없으면 숫자 없이 세션 목록만 둔다.

| 숫자 | 계산 |
|---|---|
| 최장 | 그 주 세션 `LFS`의 **최댓값**(주간 요약 줄과 같은 정의) |
| 세션당 이탈 | `Σ N_int / 세션 수` |
| 순공 / 공부 / 딴짓 | 그 주 합. 딴짓 비율 = 딴짓 × 100 / 공부(정수로 버림) |
| 집중 밀도 | `Σ T_focus × 100 / Σ T_total`(정수로 버림) |
| 세션 요약 | 세션 수와 공부 시간 평균(기준선 평균 세션 길이와 같은 정의) |
| 요일별 막대 | 그 요일에 **시작한** 세션의 순공 합 |
| 공부 중 켠 앱 | 딴짓 구간을 앱별로 묶은 횟수(구간 수)와 시간. 화면만 켠 구간은 앱이 아니라 뺀다. 시간이 긴 순서, 같으면 횟수가 많은 순서로 5개 |

- **지난주 비교값**(최장·세션당 이탈·집중 밀도) — 보고 있는 주의 앞 주와 견준다. 앞 주에 셀 세션이 없거나 앞 주 값이 0이면 비교값을 감춘다. 화살표 방향은 **화면에 보이는 자릿수**로 견준다(시간은 1분 이상이면 분까지, 이탈은 소수 첫째 자리). 같아 보이면 화살표가 없다.
- **앱별 값은 근삿값**이다. 같은 분류의 구간을 합칠 때 가장 오래 머문 앱을 대표로 남기기 때문이다([04-timeline](04-timeline.md)).
- **1주차 격차** — 첫 기록의 주가 이번 주이고 그 주를 볼 때, 온보딩 값(`selfReportedDailyMin`)과 순공이 있으면 보인다. 실측 하루 평균 = 그 주 순공 합 ÷ 월요일부터 오늘까지의 날 수(오늘 포함). 그 주가 지나면 다시 보이지 않는다. 판정·목표에는 쓰지 않는다(§5.8).

## 누적 지표

`buildCumulativeSection` — 고른 주와 관계없이 전체 기간의 `countsInStats` 세션으로 낸다. **셀 세션이 15개 미만이면 섹션 전체를 안내 없이 감춘다.** 기준선 완화는 적용하지 않는다.

| 지표 | 계산 |
|---|---|
| 이번 달 / 지난달 / 전체 순공 | 순공 합. 달은 세션 시작 시각의 로컬 날짜로 나눈 달력 월. 지난달 값이 없거나 0이면 비교값을 감추고, 이번 달이 0이면 그 줄을 감춘다 |
| 최고·최저 집중 시간대 | 아래 |
| 최장 구간 기록 | `LFS` 최댓값과 그 세션을 시작한 날. 같은 값이 여럿이면 먼저 세운 기록. 0초뿐이면 감춘다 |
| 인식 격차 추이 | 체감을 답한 세션의 `G`를 주별로(한 주에 둘 이상이면 체감 합과 순공 합으로). 답이 있는 주만 최근 4주까지 오래된 순서, 반올림. **2주 이상일 때만** 보인다 |

**집중 시간대** — 하루를 2시간 구간 12개(`0~2시` … `22~24시`)로 나누고, 세션을 **시작 시각**이 속한 구간에 통째로 넣는다(자정을 넘겨도). 구간 밀도는 기간 합(`Σ T_focus × 100 / Σ T_total`, 정수로 버림)이다.

- 세션 5개 이상인 구간만 후보다(§5.7).
- 후보가 2개 이상이고 최고와 최저의 %가 다를 때만 두 줄을 보인다. 후보가 하나면 "최고"라고 할 근거가 없다.
- 밀도가 같으면 세션이 많은 구간, 그것도 같으면 이른 시간대를 고른다.

## 요약 문단

`ReportGenerator.generate(WeeklyReportInput): List<ReportSentence>`(`suspend`) — MVP 구현은 `TemplateReportGenerator` 하나다. 고른 주에 `countsInStats` 세션이 있을 때만 만든다(`weeklyReportInput`). domain은 쓸 문장 종류와 값만 정하고 문구는 화면이 문자열 리소스로 만든다. 문장 하나가 수치 하나에서 나온다.

| 순서 | 문장 | 쓰는 조건 |
|---|---|---|
| 1 | `세션 18회, 공부 27시간 30분 중 순공은 최대 21시간 24분이었어요.` | 늘 |
| 2 | `지난주보다 순공이 3시간 20분 늘었어요.` / `줄었어요.` / `순공은 지난주와 같았어요.` | 앞 주에 셀 세션이 있을 때. 화면에 보이는 자릿수(1분 이상이면 분까지)로 뺀다 |
| 3 | `최장 구간 기록을 47분으로 갱신했어요.` | 그 주 `LFS` 최댓값이 그 주보다 앞선 셀 세션의 최댓값보다 **길 때**. 앞선 기록이 없거나 0초뿐이면(첫 주) 쓰지 않는다 |
| 4 | `이탈 31회 중 12회는 카카오톡에서 있었어요.` | 이탈이 있을 때. 이탈 횟수가 가장 많은 딴짓 앱(같으면 시간이 긴 앱). 앱별 횟수(근삿값)가 이탈 합보다 크면 쓰지 않는다 |

- 좋다·나쁘다를 말하지 않는다. 늘었으면 늘었다고, 갱신했으면 갱신했다고만 쓴다.
- 이탈은 동반 발생으로만 쓴다("~때문에" 없음, §5.5). "주로"라고 단정하지 않고 몇 회 중 몇 회인지 쓴다.
- 지난 주를 골라도 맞도록 "이번 주"라는 말을 쓰지 않는다.
- §7.5의 `verdict`·`goal` 인자는 없다. LLM 구현체를 붙일 때 `WeeklyReportInput`과 `ReportSentence`를 늘린다.

## 표본 수

- 기준선은 12세션(완화 시 6), 누적 섹션은 15세션부터 쓴다.
- 집중 시간대는 구간당 5세션 이상만 보이고 `(12세션)`처럼 표본 수를 함께 쓴다(§5.7).
- 순공 합계는 표본으로 추정한 값이 아니라 그대로 더한 값이라 표본 수를 붙이지 않는다. 인식 격차 추이는 주마다 1세션(주 1회 질문)이라 붙이지 않는다.

## 지표 규칙 버전

`MetricsVersion` — 세션의 `metricsVersion`에 함께 저장한다.

| 값 | 뜻 |
|---|---|
| `NOT_COMPUTED = 0` | 지표를 계산하지 않았다(진행 중 세션, 권한 없이 끝낸 세션) |
| `CURRENT = 1` | PLAN.md P0-3 확정 지표·임계값(2026-09-30) |

지표를 세션에 저장하므로 규칙이 바뀌면 이전 세션 값이 새 규칙과 어긋난다. 다음 중 하나가 바뀌면 `CURRENT`를 올리고, 저장 버전이 낮은 세션을 다시 계산할 대상으로 본다.

- 지표 정의(`AWAY` 제외 규칙 포함)
- 복원 알고리즘(입력 이벤트, 흡수 임계값, `KEYGUARD_HIDDEN` 규칙, 병합 순서)
- 구간 분류의 의미(`Category`)

다시 계산하는 코드는 아직 없다. 지금까지 버전은 1 하나뿐이다.

## 시간 표기

`durationParts(초)` — 1분 미만은 초, 1시간 미만은 분, 그 이상은 시간과 분(분이 0이면 시간만). **남는 분·초는 버린다.**

| 함수 | 쓰는 곳 | 예 |
|---|---|---|
| `sessionDurationText` | 세션 단위(리포트, 세션 목록, 주간 요약 줄, 다이얼로그, 체감 입력 안내, 온보딩 슬라이더) | `40초`, `25분`, `2시간`, `1시간 28분` |
| `totalDurationText` | 주간·누적 총량 — 기록 탭 순공/공부/딴짓, 판정 근거의 순공, 주간 순공 목표, 누적 섹션 순공 | `40s`, `25m`, `2h`, `21h 24m` |
| `formatElapsedClock` | 타이머 RUNNING 경과 시간 | `01:11:18` — 늘 `HH:MM:SS`, ASCII 숫자 |

- 버려서 0초가 된 길이는 세션 단위에서 `1초 미만`으로 쓴다(세션 내내 딴짓인 순공, 1초가 안 된 세션 등). 0을 보이지 않기 위해서다.
- 예외: 리포트 격차 포스트잇의 체감 0분은 사용자가 적은 답이라 `0분` 그대로 쓴다.
- 예외: 요약 문단은 문장 안이라 총량도 `sessionDurationText`(`21시간 24분`)로 쓴다. `21h 24m` 뒤에는 붙일 조사(이었/였, 으로/로)를 정할 수 없다.

## 0을 보이지 않는 곳

숫자가 0으로 떨어지면 0을 쓰지 않고 줄을 감추거나 문장으로 바꾼다.

| 자리 | 0일 때 |
|---|---|
| 주간 요약 줄 | `첫 세션을 시작해보세요` |
| 리포트 최장 구간 | 숫자를 두지 않고 조각 수만 |
| 리포트 조각 수(이탈 0회) | `이 세션에는 이탈이 없었어요` |
| `세션 1시간 38분 중 35%` | 0%로 떨어지거나 착석이 0이면 줄을 두지 않는다 |
| `기록 47분` | 다른 세션의 기록이 0초뿐이면 줄을 두지 않는다 |
| 총량 줄의 딴짓 | `· 딴짓 0분`을 쓰지 않고 `공부 …`만 |
| 집중 밀도 카드 | 0%면 카드를 두지 않는다 |
| 세션 단위 시간 | `1초 미만` |
| 기록 탭 세션당 이탈 0 | `이탈이 한 번도 없었어요` |
| 기록 탭 딴짓 | 0이면 줄을 두지 않는다. 비율만 0%면 비율만 뺀다 |
| 기록 탭 집중 밀도 | 0%면 줄을 두지 않는다 |
| 요일별 막대 | 순공 0인 날은 막대 없이 요일만 |
| 지난주 비교값, 판정 근거의 `(평소 …)` | 견줄 값이 0이면 감춘다 |
| 판정 근거 | 0인 값의 줄을 두지 않는다 |
| 누적 이번 달 순공 | 0이면 줄을 두지 않는다 |
| 누적 최장 기록 | 0초뿐이면 줄을 두지 않는다 |
